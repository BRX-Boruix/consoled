# consoled

BORUIX 的**终端字节生产者守护进程**：读键盘事件流，转换成字节，写入控制台设备。

[English](README.en.md)

## 数据链

```
键盘事件流 → 键位映射（转字节）→ 控制台设备
```

本进程是**常驻守护进程**：无参数、不退出（只在装配失败时退出）。

## 为什么转换放在用户态

键位映射是**策略而非机制**。内核的标准输入保持**原始字节流**，布局、转义、控制键折叠全部上移到
本进程。这样调整映射规则不需要动内核。

## 失败时的行为

| 情况 | 处理 |
| --- | --- |
| 事件流或控制台打不开 | 如实报错并**退出非零**（装配错误，不静默） |
| 事件读返回"稍后重试"哨兵 | **原样继续**——它是重试信号，既不是错误也不是文件结束 |
| 控制台缓冲已满 | **丢弃剩余字节并计数**，**绝不重试** |
| 其他读错误 | 如实报错退出——环损坏属于内核缺陷，硬扛无意义 |

**"绝不重试"这一条需要说明**：本进程是单线程的。缓冲满意味着读者在 100 毫秒级都没有消费——而人
手键入的速率远低于一个 4 KiB 环的排空速率，所以这种形态只出现在**读者不存在**的时候。此时若原地
重试，会**饿死事件读取侧**，连键盘输入都收不到。丢弃并计数，是唯一不会自我锁死的选择。

## 可观测性

周期性（每 256 个事件）向串口打印一行统计，包括丢弃计数，便于在不打断运行的前提下观察状态。

## 构建

```bash
cargo build --release
```

由系统初始化进程在启动时拉起，之后常驻运行。

## 文件结构

```
consoled/
├── Cargo.toml    # 包定义
├── build.rs      # 注入链接脚本
├── linker.ld     # 用户态段布局
└── src/
    └── main.rs   # 事件读取、转换与写出
```
